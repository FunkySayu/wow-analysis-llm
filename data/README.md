# data/ — long-term datasets

Data that more than one conversation will read. Per-report working extracts go to
`scratch/` instead. Everything here is regenerated by a tool under `tools/`, never
hand-edited, and the tools resolve paths through
[tools/datalayout.py](../tools/datalayout.py) — change the layout there, not in each script.

```
data/
  raid/
    timers.schema.json                       schema for every timers.json
    <patch>/<tier>/                          e.g. 12_1/venomous_abyss/
      general.json                           zone + encounter order, dir names, every id
      <nn>_<boss>/                           nn = journal order; 00 is the Lair boss
        journal.json                         Adventure Journal entry
        timers.json                          NSRT ability timers
        profiles/<spec>-<difficulty>.json    the boss measured from the ranking pool
        plan_suggestions/<spec>-<difficulty>.json
  classes/
    specs.json                               Blizzard class/spec ids -> directory names
    talents.schema.json                      schema for every <patch>_talents.json
    <class>/<spec>/                          e.g. druid/balance/
      <patch>_talents.json                   validated talent tree
      <patch>_cooldowns.json                 labels for the cooldowns plan_suggestions finds
      <patch>_loot_sources.json              KeystoneLoot: zone -> items this spec can use
      apl/                                   simc APL snapshots
  items/<patch>/items.json                   item tooltip cache (Wowhead), itemId-keyed
  external/                                  third-party API specs
```

Conventions:

- **Version by patch, everywhere** — `12_1`, as a folder under `raid/`, `dungeons/` and
  `items/`, and as a filename prefix under `classes/`. A season maps to a patch (S2 = 12.1).
- **Directory names are snake_case** (`venomous_abyss`, `death_knight`). The slugs the tools
  take on the command line stay kebab-case (`--zone venomous-abyss --spec balance-druid`);
  `general.json` and `specs.json` hold the mapping.
- **One file per encounter.** A per-encounter file is
  `{"meta": {..., "encounter": <slug>}, "encounter": {...}}`. `datalayout.load_tier()`
  stitches a tier back into `{"meta", "encounters": [...]}` for code that wants every boss.
- **A spec-filtered dataset lives under the spec**, even when it is about a raid
  (`<patch>_loot_sources.json` is Balance's view of every zone's loot).

## What each dataset is, and the trap it exists to handle

- **`classes/<class>/<spec>/<patch>_talents.json`** — built by
  `tools/raidbots/talent_tree_sync.py --class <id> --spec <id>` (`--list` prints the ids);
  regenerate when the PTR build moves. Covers Balance, Feral, Fire and Frost. Frostfire's
  subtree names a node the feed never defines; such ids are kept in `undefined_node_ids`
  rather than crashing the build. Arcane has only the older raw Raidbots dump
  (`classes/mage/arcane/12_1_ptr_talents_raidbots.json`), not the validated format.
- **`raid/.../plan_suggestions/`** — **first-draft timeline rows derived from the ranking
  pool**, built by `tools/warcraftlogs/plan_suggestion_sync.py` and loaded by the site's seeder
  as `source="suggested"` entries that carry their own evidence. Read
  [docs/design/60-plan-suggestions.md](../docs/design/60-plan-suggestions.md) before
  regenerating: every time is *phase-relative* (sampled kills on one boss ranged 317–465s, so
  an absolute-second median is a median of different fights), pulls whose phase structure
  differs from the pool's are dropped with a stated reason, and the candidate cooldown set is
  **derived from observed casts rather than a curated id list** — the talent tree's
  Incarnation (394013) and Celestial Alignment (395022) are *not* the ids the cast log uses
  (102560/194223), and filtering on them matches nothing with no error.
  `classes/<class>/<spec>/<patch>_cooldowns.json` only labels what the sample already found.
- **`raid/.../journal.json`** — **the ability catalogue**: every encounter's Adventure Journal
  entry, built by `tools/game_knowledge/journal_sync.py`. Blizzard's journal endpoint supplies
  the structure (ability hierarchy, spell ids, per-role sections, difficulty modes) and
  Wowhead's tooltip API supplies the text and the **tuned damage numbers** — the two are both
  needed because an ability section carries no description and `/data/wow/spell/<id>` **404s
  on every boss spell id in this tier**. A magnitude here is one difficulty's value and the
  endpoint does not say which, so cross-check it against measured damage in `profiles/`
  before quoting it as a Mythic number. The damage regex's school list is *derived from the
  corpus*, not remembered: an eight-school list from memory silently dropped every Plague and
  Frostfire hit, and a school it does not know looks exactly like an ability that deals no
  damage.
- **`raid/.../profiles/`** — **the boss measured, not declared**: phase transitions,
  per-ability occurrence timings, raid composition and damage taken, from the top-N ranked
  pulls for one spec and difficulty. Built by `tools/warcraftlogs/encounter_profile_sync.py`;
  read [docs/design/63-encounter-profiles.md](../docs/design/63-encounter-profiles.md) before
  regenerating. Four traps it exists to handle, each of which produced a wrong answer first:
  an **ability is a name, not a spell id** (Raging Crosswinds is five ids, Mutilate is two, so
  keying on the id draws five lanes for one mechanic); **one instance is a burst of casts**
  (those five ids fire nine casts inside one second — raw casts say 54, instances say 6);
  **phases cycle**, so the index in `phaseTransitions` is a *segment*, not a phase number
  (Sszorak reads 1,2,1,2,1,2,1 and has no phase 7); and **the enemy cast stream contains
  player abilities** — WCL attributes Anti-Magic Zone to a synthetic `Environment` actor
  flagged `subType: Boss`. That last one is caught by joining every logged ability against
  `journal.json`, never by a hand-maintained deny list, and the join is reported in both
  directions.
- **`raid/.../timers.json`** — NSRT's per-ability timers, built by
  `tools/game_knowledge/nsrt_timer_import.py`; validated by `raid/timers.schema.json`.
  Difficulty keys are the in-game ids (14/15/16), never WCL's 3/4/5.
- **`items/<patch>/items.json`** and the KeystoneLoot files — see the `keystoneloot-favorites`
  skill for the chain that builds them.

## Known gap

`site/` still reads the pre-reorganisation paths (`data/talent_trees/`,
`data/boss_timers/`, `data/plan_suggestions/`, `data/items.json`,
`data/keystoneloot_sources.json`) and has not been ported to this layout yet.
